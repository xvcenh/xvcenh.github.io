# 吞噬之潮 ·「逃离实验室」视觉素材规格清单

> **版本 v2（已修订内部不一致，可直接交付生成）**
> 本文件是给图像生成工具/画师的**投喂规格**。按此生成即可直接拖入项目。
> 代码端有兜底：任何素材缺失时游戏继续用现有程序化绘制运行，**可分期交付，不必凑齐**。
>
> **交付源目录**：`devour-tide/source/public/img/<组名>/<文件名>.png`
> **运行时 URL**：`./img/<组名>/<文件名>.png`（`base: './'`，与 index.html 同目录）

## 0. 全局规范（必读）

| 项 | 要求 |
|---|---|
| 运行环境 | Canvas 2D 游戏精灵，背景为极深海水（`#051f38` → `#010206`） |
| 格式 | PNG 透明底，禁用不透明背景 |
| 朝向 | 游动类角色一律**朝右**，游戏中按游动方向水平翻转；机械装备按各条说明 |
| 锚点 | 角色类 = 图像中心；宽幅横条（chaser） = **底边中心** |
| 尺寸 | 见各表。**@2x 仅角色/Boss/UI 需要，宽幅横条不出 @2x**（见 §0.3） |
| 风格 | 现代扁平矢量插画 + 轻霓虹发光边缘；**剪影可读性第一**（缩到 64px 仍能认出是什么） |
| 光源 | **仅允许顶部柔光 + 自发光元素；禁止侧向硬光、禁止投影/环境反射**（游戏内会大量旋转翻转，侧光会露馅） |
| 禁止 | 图内出现任何文字/字母/数字/水印、照片写实风、明显景深虚化 |
| 附加 | 单帧静态图即可；序列帧只有 `fx/bubble-sheet.png` 需要 |

### 0.1 路径与构建约定（已定稿）

```
devour-tide/
├─ source/
│  ├─ public/img/          ← 【素材放这里】Vite 构建时原样拷贝
│  │   ├─ chaser/  boss/  player/  enemy/  ui/  story/  fx/
│  └─ src/                 ← 代码
├─ index.html              ← 构建产物
└─ assets/                 ← 构建产物（JS/CSS），**不要放图片**
```

- `devour-tide/assets/` 已被 Vite 用于输出 JS/CSS（`index-*.js`），图片混入会与构建产物纠缠。
- 素材走 `source/public/img/` → `npm run build` 后**自动拷贝**到 `devour-tide/img/`，与 `assets/` 互不干扰。
- 新增素材**无需改任何配置**，放下即可被拷贝；`npm run dev` 开发时也从同一目录提供，无路径差异。
- 已实际验证：`source/public/img/chaser/` 构建后在 `devour-tide/img/chaser/` 生成。

> **注意**：`devour-tide/img/` 是构建产物（与 `assets/` 同为入库内容），所以图片在仓库里会有「源 + 产物」两份。
> P0+P1 全部到齐预计 15~20MB，翻倍后仍在可接受范围；若后续觉得仓库偏大，再改成 CI 构建时生成即可，不影响本清单的交付路径。

### 0.2 渲染与染色体（影响画法）

- 敌鱼/玩家鱼游戏内用 `c1`（体色）/`c2`（发光色）两个字段，接入后代码仍会用它们做**染色兜底与光效叠加**。
- 因此：主体请用**中性明度的固有色**，不要整体压得太暗或太亮——过暗染色后发黑，过亮染色后发白。
- 发光元素（眼、灯、能量纹）请**独立成块且边缘清晰**，便于代码做辉光叠加。

### 0.3 @2x 规则（修订）

| 类别 | 1x | @2x | 理由 |
|---|---|---|---|
| chaser 宽幅横条 | 1920 宽 | ✘ 不要 | 运行时**只会被缩小**（见 §1），出 3840 宽纯属浪费体积 |
| Boss | 512 / 640 | ✔ 必需 | 2K 屏 DPR2 时需 ≥1024 物理像素 |
| 玩家鱼 / 敌鱼 | 128 | ✔ 必需 | 大个体经缩放在宽屏上约 260 逻辑像素 |
| UI 外壳 | 表内尺寸 | ✔ 必需 | 紧贴屏幕，缩放最明显 |
| 演出图 / 标题图 | 1280×720 | 可选 | 铺满屏，DPR2 下有收益但体积大 |

## 1. 追赶者 · 人类装备下缘（P0，5 张）

**视觉概念**：追赶者是「从画面顶部压下来的危险带」。只画**下边缘一排装备**，上缘做渐隐透明（代码会向上叠加深色渐变）。

### 硬要求（务必遵守）

1. **横向必须无缝平铺**：左边缘与右边缘必须能对接，接缝处不能有元素被切断或出现明显重复节奏。代码按视口循环绘制。
2. **按 1920 逻辑像素宽设计，运行时缩放**：实际视口 1280~2560 都常见，即 0.67x ~ 1.33x。**不要表现小于 8px 的细节**，缩小后会糊成噪点。
3. 主体装备元素**避开左右各 5% 安全边距**，否则平铺时会出现「半个船头」。
4. 高度方向：装备主体集中在图像**下 60%**，上 40% 逐渐透明。

### 4.1 水母的半透明怎么做（修订）

**不要整体降低图层不透明度**（代码会叠加染色，整体降 alpha 后会发灰发脏）。要求：

- 伞体由**中心向边缘做 alpha 渐变**：中心 ≈ 0.85 → 边缘 ≈ 0.15，透明区真实穿透背景。
- 触须单独分层，alpha ≈ 0.5，末端继续降低。
- 轮廓边缘保留一条**不透明的浅色描边**（`#f5d0fe` 40% 以内），保证在深色背景与染色后仍能看清形状。

## 代码接入约定（给开发侧的备忘）

- 新增 `src/assets.js`：`Promise` 预载全表 + **逐张失败回退**（任一张加载失败/缺失 → 该元素继续走程序化绘制，游戏不报错不中断）。
- 素材源目录 `source/public/img/`，运行时路径 `./img/<组>/<文件名>.png`；`@2x` 由加载器按 `devicePixelRatio > 1.5` 自动择源。
- 精灵图在游戏中大量旋转/翻转：**仅顶部柔光 + 自发光，禁止侧向硬光与投影**。
- `c1/c2` 双色字段在接入后仅作为调色兜底与光效染色；主体请用中性明度固有色，避免染色后发黑/发白。
